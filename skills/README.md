# skills

One folder per skill, each holding a `SKILL.md`. `metadata.type` says what each one is:

- `runbook`: an ordered procedure with a check at each step: getting started, troubleshooting, migrating,
  building a connector.
- `resource`: one Stacksync resource: what it is, what it connects to, and every operation on it.
- `blueprint`: a reusable design that combines resources: when to use it, why, and how to build it.
- `solution`: a blueprint built end to end between named apps, proven on a live workspace.

Start from a folder in `templates/` and follow [CONTRIBUTING.md](../CONTRIBUTING.md). The list
below is written by `node scripts/generate-catalog.mjs`; do not edit it by hand.

### Runbooks

| --- | --- |
| [getting-started](getting-started/SKILL.md) | Connects the Stacksync MCP server to an AI app, picks the workspace and region, lists the skills and routes each request to the resource skill, blueprint or runbook that covers it. Use when someone is new to Stacksync, asks what Stacksync can do, wants to connect Stacksync to their AI app, or does not know where to start. |
| [building-a-connector](building-a-connector/SKILL.md) | Connects Stacksync to an app that has no Stacksync connector, first with an HTTP request step or a code step in a workflow, then by building a workflow connector with the Stacksync CLI, testing it locally and deploying it on request. Use when an app is missing from the Stacksync connector list, someone asks to build a custom connector or a new workflow module, or a workflow needs an API Stacksync does not cover. |
| [exploring-data-and-logs](exploring-data-and-logs/SKILL.md) | Reads sync counts, sync issues, workflow runs and Genie activity through the Stacksync MCP, sends a sync's activity to the person's own URL, and names the one web app place for what the MCP cannot read. Use when someone asks how many records a sync holds, how a sync, workflow or Genie is doing, where to find logs, how long logs are kept, how to see trends over time, or how to get alerted. |
| [migrating-to-stacksync](migrating-to-stacksync/SKILL.md) | Moves integrations and automations from another integration or automation platform to Stacksync in order: inventory, export, mapping to syncs, workflows, queues and variables, build, parallel run on test records, comparison, cutover and rollback. Use when someone wants to move existing integrations, automations or data pipelines to Stacksync, retire another platform, or plan a cutover without losing data. |
| [troubleshooting-a-genie](troubleshooting-a-genie/SKILL.md) | Finds why a Stacksync Genie or its scheduled task failed or seems stuck and fixes it in order: locate the conversation, read its steps and errors, explain the cause, suggest a fix, apply it after the person's yes, and confirm. Use when a Genie answered wrongly, failed, stopped responding, or a Genie task did not run or ran at the wrong time. |
| [troubleshooting-a-sync](troubleshooting-a-sync/SKILL.md) | Finds why a Stacksync sync misbehaves and fixes it in order: locate the sync, read its health and issues, explain the cause, suggest a fix, apply it after the person's yes, and confirm the next sync succeeds. Use when records are not syncing, a sync shows issues or errors, a sync is paused by errors, data differs between the two apps, or changes are stuck or slow. |
| [troubleshooting-workflow-runs](troubleshooting-workflow-runs/SKILL.md) | Finds why Stacksync workflow runs failed and fixes them in order: locate the failed runs, read the failing step's input, output and error, explain the cause, suggest a fix, replay on the fixed version after the person's yes, and confirm the new runs succeed. Use when a workflow failed or did not run, someone asks why a step errored or what it received, or failed runs need a fix and a replay. |

### Resources

| Skill | Description |
| --- | --- |
| [api-proxies](api-proxies/SKILL.md) | Lists, reads, creates, renames, shares, moves to another connection and deletes Stacksync managed API proxies, which give scripts and internal tools one HTTPS endpoint and one access token for the API of a connected Salesforce, HubSpot, Pipedrive, Attio or Airtable account. Use when someone wants to call one of those APIs from their own code without handling its sign in, needs an API proxy or its token, or a script calling an API proxy stopped working. |
| [connections](connections/SKILL.md) | Lists, creates, reads, renames, shares, reauthorizes and deletes Stacksync connections, reads the live tables and columns of a connected app, and explains network options and app rate limits. Use when someone wants to connect an app or database, a connection expired or needs reauthorization, a teammate cannot see a connection, a connection must be deleted, someone asks which tables or fields an app has, or a database sits behind a firewall or in a private network. |
| [connectors](connectors/SKILL.md) | Finds apps and built-in modules in the Stacksync catalog through the Stacksync MCP, shows an app's actions, triggers and connections, fills an action's form, and runs one app action on its own without a workflow. Use when someone asks which apps or actions Stacksync offers, what an app can do, or wants to look up, find, create, update or delete a record in an app right now, or try an action before putting it in a workflow. |
| [files](files/SKILL.md) | Lists and reads the details of files stored in a Stacksync workspace (name, type, size, tags, region and what each file belongs to), such as knowledge base uploads, email attachments and files workflows or Genies wrote. Use when someone needs a file_id, looks for a file in the workspace, or asks where a file came from or how large it is. |
| [folders](folders/SKILL.md) | Finds any Stacksync resource by name across every type, and creates, renames, moves and deletes folders. Use when someone asks where a sync, workflow or Genie is, cannot find a resource, wants to tidy the workspace, group resources by team or project, move resources into a folder or back to the root, or delete a folder. |
| [genies](genies/SKILL.md) | Creates, changes, shares, asks, monitors and deletes Stacksync Genies, the AI agents that act in a workspace's apps, with their skills (app actions), knowledge bases, Slack, Microsoft Teams and email interfaces, approvals and scheduled or one-time tasks. Use when someone wants an AI agent or assistant that answers in Slack, Teams or email, wants to build, change, share, test or delete a Genie, ask a Genie something, approve or reject a Genie action, see what a Genie did or cost, or have a Genie do something on a schedule or once at a set time. |
| [internal-apps](internal-apps/SKILL.md) | Deploys a hosted internal app, a managed PostgreSQL database, file storage or an internal API with Stacksync Enterprise OS through its CLI, and connects the app to Stacksync workflows. Use when someone wants to host a web app, portal, dashboard or API for their team, needs a managed database or file storage behind it, or asks for software that syncs and workflows do not provide on their own. |
| [knowledge-bases](knowledge-bases/SKILL.md) | Creates, renames, shares and deletes Stacksync knowledge bases, the document collections Genies answer from, and adds or removes their documents from workspace files (PDF, Word .docx, Excel .xlsx, CSV, JSON, Markdown and plain text). Use when someone wants a Genie to answer from their own policies, catalogs or manuals, wants to add or remove a knowledge base document, or asks why a document failed to process. |
| [queues](queues/SKILL.md) | Lists, reads, creates, changes, pauses, flushes, clears and deletes Stacksync queues, which collect records from producers and hand them to one consumer workflow in batches by flush rules for batch size, maximum age, rate limit and order. Use when someone wants to process many changes at a steady pace, batch records between a sync or workflow and a workflow, set how often a queue flushes, see what waits in a queue, push waiting records through now, or empty or remove a queue. |
| [syncs](syncs/SKILL.md) | Creates, edits, copies, starts, pauses and deletes Stacksync syncs that keep records equal between two apps, plans one-way or two-way direction per table, resolves failed records, and adds sync event triggers and sync webhooks. Use when someone asks to set up or change a sync, choose sync direction, add a table or field, change how often a sync runs, switch a sync on or off, retry or ignore failed records, or run a call, query or queue message when synced records change. |
| [variables](variables/SKILL.md) | Lists, reads, creates, changes and deletes Stacksync workspace variables and secrets, and shows how workflow steps read them by reference. Use when someone wants to store a value that workflows share, such as an account ID, a threshold, a cursor or an API token, asks how a step reads a variable or secret, wants to change a value every workflow uses, or a workflow reads the wrong or an empty value. |
| [workflows](workflows/SKILL.md) | Builds, changes, runs and deploys Stacksync workflows through the Stacksync MCP, from the workflow document, triggers (webhook, schedule, email, Gmail, queue), steps, code steps and data references to test runs, run logs, replays, resolved runs, drafts, copies and deletes. Use when someone wants to automate a process, create or edit a workflow, add a step or a trigger, run a workflow now, read what a run did, replay or resolve runs, put a version live, copy a workflow to another region, or pause, share or delete one. |
| [workspaces](workspaces/SKILL.md) | Shows the person's workspaces, role and data regions, lists workspace members and groups, and sends the person to the web app for invitations, roles, groups, MFA, SSO, API keys and the workspace's AI settings. Use when someone asks which workspace or role they have, who is in the workspace, wants to invite a colleague or change a role, asks about MFA, single sign on or user provisioning, or wants to turn on "Ask before every change" or limit what AI apps may do in the workspace. |

### Blueprints

| Skill | Description |
| --- | --- |
| [alert-on-sync-issues](alert-on-sync-issues/SKILL.md) | Sends a team a message or email when a sync has failed records, through a sync webhook of type real_time_issue_notification that calls a workflow. Use when someone wants to be told about sync errors as they happen instead of checking the sync, or wants failed records routed to a channel, an inbox or a ticket. |
| [api-proxy-for-an-app](api-proxy-for-an-app/SKILL.md) | Gives a script, an internal tool or a partner access to one app's API through a Stacksync API proxy bound to a connection, so callers use a proxy token and never hold the app's own credentials. Use when someone's code needs to call an app's API directly, and the app login should stay in Stacksync. |
| [batch-sync-changes-through-a-queue](batch-sync-changes-through-a-queue/SKILL.md) | Collects the records a sync changes in a Stacksync queue and hands them to one workflow run per batch, with flush rules for batch size and maximum wait. Use when changes arrive in bursts of hundreds or thousands, when one run per record is too many runs, or when the receiving app accepts records in bulk. |
| [chain-workflows](chain-workflows/SKILL.md) | Hands work from one workflow to another, through an HTTP step that calls the next workflow's webhook URL or through a queue that the next workflow consumes. Use when a process is split into separate workflows owned or deployed separately, or one workflow should start another. |
| [database-replica-of-an-app](database-replica-of-an-app/SKILL.md) | Keeps a copy of an app's tables in a database, one-way from the app, so teams query, join and report on the app's data with SQL. Use when someone wants app data such as CRM, ERP or e-commerce records in their own database or warehouse for analytics, backups or other systems to read. |
| [enrich-records-after-a-sync](enrich-records-after-a-sync/SKILL.md) | Adds missing company and contact data, such as industry, size, email or phone, to records that a sync creates or changes, using the built-in enrichment and validation steps, and writes the result back to the app. Use when someone wants new leads, contacts or accounts filled in or checked automatically after they reach an app or database. |
| [inbound-email-to-records](inbound-email-to-records/SKILL.md) | Turns incoming emails, such as orders, invoices or requests, into records in an app, through a workflow started by a new email in the person's own Gmail mailbox or by an email sent to a Stacksync address. Use when someone wants emails or their attachments read and turned into records, tickets or rows automatically. |
| [inbound-webhook-to-records](inbound-webhook-to-records/SKILL.md) | Receives HTTP calls from another system on a workflow's webhook URL and turns each call's body into records in an app. Use when a system can send webhooks or POST requests, such as form submissions, payment events or partner notifications, and each one should create or update records. |
| [knowledge-grounded-email-genie](knowledge-grounded-email-genie/SKILL.md) | Sets up a genie with its own Stacksync email address that answers incoming emails from documents in a knowledge base and can look up or act on records through app actions, with approval on actions that change data. Use when someone wants an AI assistant that replies to customer, supplier or internal emails using company documents and app data. |
| [react-to-each-record-change](react-to-each-record-change/SKILL.md) | Runs one workflow for each record that is created, updated or deleted in a connected app, through a workflow sync trigger or a sync event trigger that calls the workflow's webhook. Use when someone wants an action per changed record at low volume, such as notifying a team, creating a follow-up record or calling an API each time one record changes. |
| [reverse-etl-from-a-warehouse](reverse-etl-from-a-warehouse/SKILL.md) | Copies modelled data, such as scores, segments or account health, from a data warehouse table or view into the matching fields of an operational app, through a one-way sync. Use when someone wants numbers computed in a warehouse to appear in a CRM, support tool or ERP for the teams who work there. |
| [scheduled-genie-task](scheduled-genie-task/SKILL.md) | Gives a genie a task that runs on a cron schedule in UTC or once at a set time, such as a morning summary, a weekly review of open deals or a check of overdue invoices, answered with the genie's app actions and knowledge. Use when someone wants an AI to do a recurring review or report that needs judgement, not fixed steps. |
| [scheduled-workflow](scheduled-workflow/SKILL.md) | Runs a workflow on a cron schedule in UTC to pull, check, report or clean up data at fixed times. Use when work should happen every few minutes, hourly, daily or weekly rather than on each change, such as a nightly report, a daily reconciliation or an hourly import from an API without webhooks. |
| [throttle-writes-with-a-queue](throttle-writes-with-a-queue/SKILL.md) | Puts a Stacksync queue between workflows that produce records and the workflow that writes them, so writes reach a rate limited app at a set pace and in batches. Use when an app rejects calls with too many requests, when bursts of events must be smoothed, or when several workflows write to the same app. |
| [two-way-sync-between-apps](two-way-sync-between-apps/SKILL.md) | Keeps the same records in two apps or an app and a database in step, with edits in either app copied to the other, direction chosen per table and safeguards for duplicates and deletes. Use when people edit the same records in two places and both must see each other's changes, such as a CRM and an ERP, or an app and a team's database. |
