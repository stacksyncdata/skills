# Postgres

Notes for syncing Postgres, from the public Postgres connector pages at
docs.stacksync.com/two-way-sync/connectors/postgres.

## Table requirements

- Every table needs a **single-column primary key**; composite keys do not work.
- The primary key must be **generated by the database** (a default value), such as
  `id uuid PRIMARY KEY DEFAULT gen_random_uuid()` or `id serial PRIMARY KEY`.
- The database user Stacksync connects with must own the tables, or hold the owner's role.

A table that is in the database but not in `connections_tables` fails one of these.

## Required permissions

The least a user needs, replacing the names in capitals:

```sql
CREATE USER stacksync_user WITH PASSWORD 'STRONG_PASSWORD';
-- tables Stacksync creates for its own tracking
CREATE SCHEMA IF NOT EXISTS stacksync_logging;
GRANT ALL PRIVILEGES ON SCHEMA stacksync_logging TO stacksync_user;
-- triggers on the synced tables
GRANT CREATE ON DATABASE DATABASE_NAME TO stacksync_user;
GRANT USAGE, CREATE ON SCHEMA SCHEMA_NAME TO stacksync_user;
GRANT USAGE ON LANGUAGE plpgsql TO stacksync_user;
GRANT SELECT, INSERT, UPDATE, DELETE, TRIGGER ON TABLE TABLE_NAMES TO stacksync_user;
-- finding which tables can sync
GRANT SELECT ON pg_class TO stacksync_user;
GRANT SELECT ON pg_namespace TO stacksync_user;
GRANT SELECT ON pg_constraint TO stacksync_user;
GRANT SELECT ON pg_attribute TO stacksync_user;
GRANT SELECT ON pg_attrdef TO stacksync_user;
GRANT SELECT ON information_schema.sequences TO stacksync_user;
```

- **PostgreSQL 12 and earlier**: a database administrator runs
  `CREATE EXTENSION IF NOT EXISTS pgcrypto;` before the sync is created.
- **Partitioned tables**: partitions that existed before the grants need the same table grants;
  later partitions inherit them.

## Change capture

The Postgres connector needs replication rights. The error "The user does not have the right
permissions for replication" means the user lacks them. Two ways out:

- Use the **Postgres Heroku** connector for that database, whoever hosts it. It works without
  replication rights, at a small database cost, and needs the `CREATE` privilege on the database.
- Or grant replication (`ALTER ROLE stacksync_user WITH REPLICATION;`, run by a superuser), set
  `wal_level = logical` in `postgresql.conf`, restart Postgres, check with `SHOW wal_level;`, and
  use the Postgres connector.

`syncs_get` shows a database app's change capture method as `cdc_method`: `triggers` or
`logical_replication`. `syncs_save` changes it.

## Connecting by host

Call `connections_create` and give the person the sign in link; they enter the connection string or
the host, port, user, password and database there. An SSL root certificate and an SSH tunnel are
optional on the same page.

| Host | What to know |
| --- | --- |
| Amazon RDS | Endpoint and port on **Connectivity & security**; user and database on **Configuration** (empty database name: `postgres`). A private subnet needs a jumpbox (docs: SSH tunneling). Upload the region's RDS certificate for a verified SSL connection |
| Amazon Lightsail | Endpoint, port, user and password on the database's **Connect** tab; the user needs `CREATE` on the database |
| Cloud SQL | The instance's public IP, port 5432, a user from **Users**, a database from **Databases**; for SSL, download `server-ca.pem` from **Connections > Security** |
| DigitalOcean | Add `sslmode=no-verify` to the connection string; allow Stacksync's IP addresses if the database is restricted |
| Heroku | Use the Postgres Heroku connector; copy the **Connection URI** from the add-on's database credentials; the user needs `CREATE` on the database |
| Supabase | Use the **Transaction Pooler** connection string, IPv4 compatible (IPv6 is not supported), and type the password, as it may not be copied with the string |

## After setup

Renaming a schema, table or column breaks the sync's configuration. Pause the sync, rename, then
update the sync (see "Change fields and table pairs" in `syncs` and [schema-changes.md](schema-changes.md)).
